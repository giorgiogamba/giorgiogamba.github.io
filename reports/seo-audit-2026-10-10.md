## Diagnosi dell’email di Google

«Pagina alternativa con tag canonical appropriato» significa che Google considera una URL una copia di un’altra e riconosce il canonical. Non è di per sé una penalizzazione o un errore. Il risultato corretto è indicizzare la URL principale, non tutte le copie.

Il file index.html aveva già un unico canonical assoluto corretto:

```html
<link rel="canonical" href="https://giorgiogamba.com/">
```

L’ho mantenuto. CNAME, canonical, og:url e URL della homepage in sitemap concordano sul dominio HTTPS senza www. Rimuovere il canonical per tentare di eliminare l’avviso indebolirebbe questa coerenza.

Possibili URL alternative sono /index.html, URL con parametri, versioni HTTP, www o il dominio github.io. Sono ipotesi: senza l’elenco di Search Console non è possibile attribuire l’email a una variante specifica. Se è esclusa una copia che punta alla homepage, il comportamento è intenzionale. Se è esclusa la homepage stessa o una pagina con contenuto distinto, va controllato il canonical selezionato da Google.

La homepage pubblica è risultata leggibile con lo strumento web. Le richieste HTTP dirette hanno fallito la risoluzione DNS dall’ambiente di esecuzione, anche dopo il tentativo con accesso esteso; lo strumento web non ha recuperato le varianti. Questo non dimostra un guasto DNS del sito. Non ho quindi verificato status HTTP, catene di redirect, configurazione DNS/TLS o header di produzione. Non ho accesso autenticato a Search Console.

## Passaggi per chiudere la segnalazione

1. Pubblicare queste modifiche tramite il normale flusso del repository GitHub Pages.
2. In GitHub → Settings → Pages verificare il dominio personalizzato giorgiogamba.com e abilitare Enforce HTTPS quando disponibile. Verificare con il provider DNS la configurazione di www seguendo la documentazione GitHub, senza modificare record estranei al sito.
3. Controllare in produzione che la homepage risponda 200; le varianti HTTP/www/github.io dovrebbero convergere sul dominio preferito quando configurate. Verificare separatamente /index.html: GitHub Pages non consente di configurare liberamente redirect server per ogni percorso. Se risponde 200 con lo stesso canonical, l’esclusione come alternativa è accettabile. Non ho aggiunto redirect JavaScript né file .htaccess, inefficaci per configurare redirect HTTP su GitHub Pages.
4. Controllare che /robots.txt, /sitemap.xml e i due PDF siano accessibili e che un percorso inesistente restituisca realmente 404, senza reindirizzare alla homepage.
5. In Search Console aprire Indicizzazione → Pagine → Pagina alternativa con tag canonical appropriato ed esportare le URL interessate. Per ciascuna, usare Controllo URL e confrontare canonical dichiarato e canonical selezionato da Google.
6. Controllare anche https://giorgiogamba.com/ direttamente: deve essere la pagina principale indicizzabile. Se il canonical scelto è diverso, esaminare redirect e segnali della URL effettivamente scelta prima di ulteriori modifiche.
7. Inviare sitemap.xml nella sezione Sitemap. Dopo la pubblicazione usare Test URL pubblicato e richiedere l’indicizzazione della homepage se necessario. Il test live non predice la selezione finale del canonical. Una richiesta non garantisce né tempi né indicizzazione.
8. Se tutte le URL segnalate sono copie legittime, non occorre forzarne l’indicizzazione o azzerare il report: l’esclusione è corretta. Se erano pagine distinte escluse per errore, correggere quelle specifiche URL e avviare l’eventuale convalida disponibile.
